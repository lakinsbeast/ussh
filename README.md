# ussh

[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Удалённый шелл в духе mosh: соединение переживает обрывы и смену сети, сессия живёт на сервере, а история прокручивается и ищется.

## Установка

Готовые бинарники лежат в [Releases](https://github.com/lakinsbeast/ussh/releases):

| Платформа | Файл |
|---|---|
| macOS (Apple Silicon и Intel) | `ussh-macos` |
| Linux x86_64 | `ussh-linux-x86_64` |
| Linux aarch64 | `ussh-linux-aarch64` |

```sh
chmod +x ussh-linux-x86_64          # или ussh-macos, ussh-linux-aarch64
mkdir -p ~/.local/bin
mv ussh-linux-x86_64 ~/.local/bin/ussh   # имя файла — именно ussh
ussh -V                                  # ussh 0.1.0
```

На сервере ничего ставить не надо: клиент сам заливает подходящую сборку в `~/.local/bin/ussh`
при первом подключении. Клиент и сервер — один и тот же бинарник в разных режимах, версии
совместимы между платформами.

## Использование

```
ussh [user@]host            # новая сессия: main, main-2, …
ussh -s work host           # вернуться в сессию work (забрать её у другого окна)
ussh --list host            # сессии: attached / free и сколько простаивает
ussh --kill -s work host    # завершить сессию
ussh --clean host           # завершить сессии, к которым не подключались 7 дней
ussh --ssh="ssh -p 2222" host
```

На Mac обновлять так: `rm ~/ussh; scp host:…/dist/ussh-macos ~/ussh`. Если перезаписать бинарник поверх старого, macOS убьёт его при запуске (SIGKILL) из-за закэшированной подписи.

## Клавиши

`Ctrl-^` — это `Ctrl-6` или `Ctrl-Shift-6`.

| | |
|---|---|
| `Ctrl-^ .` | отключиться; сессия продолжает работать |
| `Ctrl-^ h` | история: `↑↓`, `PgUp/PgDn`, колесо мыши, `g/G`, `/` поиск, `n/N`, `q` выход |
| `Ctrl-^ ?` | подсказка по клавишам поверх экрана; любая клавиша её закрывает |
| `Ctrl-^ Ctrl-^` | отправить сам `Ctrl-^` |

## Как устроено

- **Бутстрап.** `ssh host ussh server connect NAME` находит сессию или запускает её (отдельный процесс через `setsid`). Сессия выдаёт свежий ключ и UDP-порт из диапазона 60001–61000.
- **Транспорт.** Свой UDP-протокол, шифрование ChaCha20-Poly1305. Заголовок пакета маскируется, поэтому у трафика нет постоянной сигнатуры. Это не QUIC: его режет ТСПУ.
- **Два канала сразу.** Тот же SSH-процесс остаётся relay-ем на всё время сессии: каждый пакет идёт и по UDP, и внутри SSH-канала, дубли отбрасываются. Relay не закрывается, когда UDP «заработал»: бывают сети (так было с Таттелекомом), которые пропускают первые секунды UDP-потока, а потом теряют почти всё. Если relay умер, клиент сразу поднимает новый. Если связь пропала больше чем на 5 с, клиент сам переподключает SSH в фоне (`BatchMode`, нужен ключ или агент). Переподключение только возвращает к той же сессии: если её уже нет, клиент пишет «session ended», а не создаёт новую на её месте.
- **Синхронизация экрана.** Сервер держит эмулятор терминала (`vt100`) и шлёт диффы «версия N → M», сжатые deflate и порезанные на фрагменты по 1100 байт. Потери не переотправляются: следующий дифф строится от последнего подтверждённого состояния. Ввод — поток байтов с адресацией по смещению, поэтому дубли и повторы безвредны.
- **Роуминг.** Сервер отвечает на адреса, с которых последние 15 с приходили валидные пакеты.
- **Сессии и окна.** Сессия привязана к имени, а не к клиенту.
  - `ussh host` всегда создаёт новую сессию: первое свободное имя из `main`, `main-2`, … Вверху окна на пару секунд появляется подсказка с её именем. Общая сессия по ошибке — хуже лишней сессии.
  - `ussh -s work host` — именно эта сессия: забрать у другого окна или создать, если её нет. Так возвращаются в свою после detach.
  - Выбор делает сервер под файловой блокировкой, поэтому окна, открытые с `-n` одновременно, получают разные сессии.
  - С `-s` — именно эта сессия: забрать у другого окна или создать.
- **Нативный скролл.** Клиент работает без alternate screen: строки, ушедшие за верх экрана на сервере, надёжным потоком (go-back-N) едут на клиент и вставляются в собственный scrollback терминала. Скролл трекпадом — нативный, без сети. При переподключении приезжают последние 1000 строк. При флуде (отставание >3000 строк) лишнее пропускается с пометкой, всё целиком лежит на сервере (до 50 000 строк) в `Ctrl-^ h`.
- **Отрисовка.** Каждый кадр выводится в synchronized output (`?2026`), поэтому без мерцания и разрывов. Клиент держит зеркало экрана (`vt100`) и перерисовывает локально, без запроса к серверу (после вставки истории, снятия баннера).
- **Задержка.** Эхо после нажатия уходит сразу (~1 мс), темп кадров ограничивается только при выводе, в который никто не печатает. SSH идёт через ControlMaster (`~/.ussh/cm-*`), поэтому пароль спрашивается один раз.

## Вставка файлов и картинок (Ctrl+V)

`Ctrl+V` проверяет локальный буфер обмена:
- если там скриншот или картинка, она заливается на сервер как `paste-<время>.png`;
- если файлы из Finder или файлового менеджера, заливаются они;
- в командную строку вставляется путь на сервере, как при drag & drop. Если программа включила bracketed paste — через него.

`Cmd+V` и перетаскивание файлов в окно тоже работают. Терминал сам вставляет локальные пути (`/Users/…/Screenshot\ ….png`, в кавычках или `file://`). Если вставка через bracketed paste целиком состоит из путей к существующим локальным файлам, они заливаются, а вместо них вставляются пути на сервере. Обычный текст и несуществующие пути уходят как есть.

Если в буфере текст, `Ctrl+V` уходит программе как обычно, например для блочного выделения в vim. `Ctrl-^ Ctrl-V` всегда шлёт обычный `Ctrl+V`.

Заливка идёт внутри самой сессии, по тому же зашифрованному UDP-каналу (или SSH-релею), что и терминал. Поэтому пароль не нужен даже через час после входа, а заливка переживает смену сети и сон ноутбука. Сервер подтверждает полученные куски, клиент досылает только потерянные. К сессиям, запущенным старой версией ussh, файлы по-прежнему идут отдельным ssh (без пароля только первые 10 минут, пока живо общее соединение); такую сессию лучше перезапустить. Можно скопировать сразу несколько файлов: зальются все, пути вставятся через пробел. Сверху показывается полоска прогресса: файл, `N/M`, проценты, объём и скорость. Нажатия, сделанные во время заливки, ждут и не обгоняют путь. `Ctrl+C` отменяет заливку. Файлы лежат в `~/.ussh/run/<сессия>.files/` и удаляются, когда сессия завершается.

Буфер читается через `osascript` на macOS (AppleScriptObjC → `NSPasteboard`: все скопированные файлы, PNG и TIFF→PNG; запасной вариант — классический AppleScript) и через `wl-paste`/`xclip` на Linux.

## Картинки (kitty graphics)

Программы, которые рисуют картинки по протоколу kitty (`chafa -f kitty`, `kitten icat`, `timg -pk`, yazi, matplotlib-бэкенды), работают через ussh, если локальный терминал — Ghostty или kitty. mosh такие картинки просто выбрасывает.

Как устроено:
- сервер вырезает команды графики из вывода программы, хранит картинки и надёжным потоком (go-back-N, с буфером на клиенте для пакетов, пришедших не по порядку) шлёт их клиенту;
- на экране картинка — сетка символов-заполнителей kitty (U+10EEEE, id картинки в цвете текста, строка и столбец в диакритиках);
- заполнители — обычный текст: синхронизируются диффами, уходят в нативный scrollback и в `Ctrl-^ h`, переживают переподключение.

На запросы программы (`a=q`, DA1, размеры в пикселях `CSI 14/16 t`, XTVERSION) отвечает сервер, как ответил бы терминал. На XTVERSION он называет терминал клиента (`ghostty 1.x` или `kitty`): по этому имени Claude Code решает, рисовать ли картинки. Файлы (`t=f`, `t=t`, `t=s`) читаются на сервере, там, где работает программа.

Новому клиенту сервер повторно отправляет только картинки, до которых ещё можно доскроллить: экран и последние 1000 строк истории. Хранится до 64 МБ. Анимация (`a=f`) не поддерживается.

Поддержка определяется по `TERM=xterm-ghostty|xterm-kitty` или `TERM_PROGRAM=ghostty`. `USSH_GRAPHICS=1/0` включает или выключает её принудительно. Без поддержки программа не получает ответа на запрос графики и сама откатывается на текст.

## Клавиатура kitty (Shift+Enter)

Программы, которые включают kitty keyboard protocol (Claude Code, Codex, neovim, helix), получают его и через ussh, если терминал — Ghostty или kitty. Тогда работают Shift+Enter, Ctrl+Enter, Alt+буква и прочее, что в обычном режиме неотличимо. Под tmux и mosh этого нет.

Сервер ведёт стек флагов (`CSI > u`, `CSI < u`, `CSI = u`) отдельно для основного и альтернативного экрана и отвечает на `CSI ? u`. Клиент выставляет те же флаги своему терминалу. Свои клавиши (`Ctrl-^` и следующую за ней, `Ctrl+V`, `Ctrl+C` во время заливки) клиент узнаёт и в виде `CSI … u`. В истории (`Ctrl-^ h`) и после выхода клавиатура возвращается в обычный режим.

## Уведомления

Звонок (BEL) и уведомления на рабочий стол (OSC 9, OSC 777 `notify`, OSC 99 kitty) доходят до терминала, каждое ровно один раз, даже при потерях. Так Claude Code сообщает, что закончил. Прогресс OSC 9;4 (Ghostty показывает его во вкладке) синхронизируется как состояние. Несколько звонков подряд звенят один раз.

Claude Code выбирает способ уведомлять по `TERM_PROGRAM`, поэтому клиент передаёт в новую сессию свои `TERM_PROGRAM`, `TERM_PROGRAM_VERSION` и `COLORTERM`. Окружение задаётся при старте сессии: в сессии, начатой до обновления, уведомлений от Claude Code не будет, пока её не перезапустишь.

## Ссылки и заголовок

Кликабельные ссылки OSC 8 (Claude Code, `ls --hyperlink`, gcc и т.п.) хранятся в каждой ячейке экрана и в истории и доходят до терминала. Для этого в `vendor/vt100` лежит пропатченная копия vt100 0.18.1 (новое — `src/links.rs`).

В заголовке окна первым идёт имя сессии: `main-2 · ✳ Claude Code`. Так вкладки различаются, даже когда заголовок обрезан.

## Буфер обмена

Копирование в удалённой программе через OSC 52 (vim с `+clipboard`/OSC52-плагином, tmux с `set-clipboard on`, многие TUI) попадает в буфер обмена локального терминала. Терминал должен поддерживать OSC 52: iTerm2 (включить «Applications in terminal may access clipboard»), Ghostty, kitty, WezTerm, Alacritty. Terminal.app — нет.

## Тестовые переключатели (клиент)

`USSH_TEST_CLIPBOARD=image:/x.png|file:/a,/b|text` — подменить буфер обмена. `USSH_DROP=0.3` — терять 30% пакетов в обе стороны. `USSH_UDP_DROP=0.9` — терять 90% UDP-пакетов от сервера (сеть, режущая UDP). `USSH_NO_UDP=1` — только через SSH. `USSH_ROAM_SECS=2` — менять UDP-сокет каждые 2 с. `USSH_BLACKHOLE=/path` — терять всё, пока файл существует.

## Сборка

```
./dist.sh          # dist/ussh-linux-x86_64, dist/ussh-linux-aarch64 (+ dist/ussh-macos)
./setup-cross.sh   # один раз: zig + cargo-zigbuild, чтобы dist.sh собрал и macOS
```

Клиент вшивает в себя серверные бинарники (`USSH_EMBED_DIR`, см. `build.rs`). Клиент под Mac сам ставит на сервер Linux-версию нужной архитектуры: выбор по `uname -sm`, а проверка по FNV-хешу бинарника (`ussh build-id`).

Отладочный лог: клиент — `USSH_LOG=/path`, сервер — если существует `~/.ussh/debug`, пишет в `~/.ussh/run/NAME.debug`.
